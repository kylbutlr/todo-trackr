The existing backoff, webhook and repair work should be retained. This patch fixes known-offline web requests and immediate refresh after reconnecting with an expired App Switchr lease. ## Verified remaining waste and limits

1. **Offline web requests, fixed here.** The main Task loop and control loop could attempt requests while navigator.onLine=false. Connection/Board hooks already gate on this signal. The new Task lifecycle preserves explicit initial/manual reads, existing due times, focus/visibility refresh and permission checks. The control loop renews permission immediately on reconnect and emits resume after an expired/unavailable lease even at an unchanged revision. Healthy permission checks do not trigger additional task refreshes.
2. **Native repeated manual reads, left for a separate native change.** Mini refresh calls syncShortcutAndReload, whose successful/ignored response already reloads open Tasks and an opened Board, then refreshMiniDashboard reads its selected surface again. This is one extra Task or Board read per applicable manual refresh. Removing it requires tests for errors/Off mode/standalone fallback and distribution to the installed client; the observed CU reduction does not justify bundling a native release here.
3. **Saved interval is not the new-install default.** This Mac's persisted preference is 15 minutes, not 60. It was not changed. Off/Review sync still does a database connection check. Choosing 60 or Off could reduce full source reconciliations but changes the independent freshness backstop; it must be a deliberate user choice.
4. **Initial metadata duplication.** Opening a web connection directly can load diagnostics in both Workspace's initial metadata request and the mounted connection view. Manual scan/accept flows can also combine a diagnostics refresh with a parent reload. These are bounded action/open costs, not persistent duplicate loops. Do not add a shared cache without mutation invalidation.
5. **Multiple clients still multiply reads.** Each browser workspace/Mac owns its own backoff and native interval. Single-flight flags apply within one component/store; they do not elect a leader across tabs/Macs. The Blob catch-up lease and SQL advisory transaction lock protect distinct correctness boundaries, not all source-fetch duplication. Independent ten-minute clients can interleave within every five-minute idle window. Leader election/shared caching would need failover, sleep, token, mutation and alarm semantics reviewed first.
6. **Repair/catch-up can repeat reconciliation.** The first repair that completes a new Switchr revision can reconcile Shortcut in resumeAutomaticWork and then again in shortcut-repair. Both aligned workers can also attempt the shared drain. The Blob lease bounds concurrent drain work, but it does not eliminate every subsequent ordinary repair. Coalescing needs missed-event/failure coverage, not simply removing the second call.
7. **Failures do not exponentially back off everywhere.** Main web tasks retry at 30s, adaptive connection reads at at least 60s, and native task failures use the current task interval. No overlapping task requests are started by their store/component guards, and native Shortcut failures wait the selected interval. A persistent server-side error can still bridge idle windows. Slower retry would delay recovery visibility; no such tradeoff is introduced here.
8. **Hidden suppression has exceptions.** Scheduled native Task reads and per-Mac source sync are hidden/sign-out gated. Startup restoration, deliberate opening, the bounded review watch, and distributed Switchr activation can read outside that scheduled path. Native has no explicit network-reachability gate in these loops. The documentation's broad hidden wording must not be interpreted as zero possible network work.
9. **Timestamp handling is already mostly correct.** Adaptive diagnostics/Board fingerprints exclude generatedAt and nextScanAt, retaining source timestamps/configuration. Shortcut nextRepairAt advances only at a six-hour boundary and can reset backoff once then. Task snapshots do not include a response clock; needsAttention changes at a real alarm boundary. Removing that field or alarm timestamps would weaken behavior.

Planning estimates, not measured savings:

- Truly offline requests cannot reach Neon. Conservative additional CU-hour savings assigned to this patch: **0**. Reconnect deliberately restores one prompt read and can cause an earlier legitimate wake.
- The already-shipped ten-minute quiet cadence is 6 reads/hour at steady state versus 120/hour at 30s, a modeled 95% request reduction for one continuously visible unchanged surface. This audit does not claim that reduction as new work.
- A voluntary native 15-to-60-minute setting change models 4-to-1 extra sync attempts per visible active hour, a 75% reduction for that source only. It changes the missed-webhook freshness backstop and does not guarantee 75% less compute.
- With an assumed 0.25 CU minimum and five-minute idle timeout, one isolated five-minute wake costs about 0.020833 CU-hours; four aligned daily windows model 0.083333 CU-hours/day. Actual settings, job duration, alarms, webhooks, autoscaling and interleaved clients can invalidate that model. [Neon scale-to-zero guidance](https://neon.com/docs/introduction/scale-to-zero) documents the five-minute default; this project's compute settings were not verified or changed.
